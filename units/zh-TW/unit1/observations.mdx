# 觀察：整合回饋、反思並調整

觀察是 **agent 感知行動結果的方式**。

觀察提供重要資訊，推動 agent 的思考過程，並引導後續行動。

這些**來自環境的訊號**，無論是 API 資料、錯誤訊息或系統日誌，都會引導下一輪思考。

在觀察階段，agent 會：

- **收集回饋：**接收資料，或確認行動是否成功。
- **附加結果：**將新資訊整合到既有的上下文，藉此更新記憶。
- **調整策略：**利用更新後的上下文，改善後續的思考與行動。

例如，天氣 API 回傳*「局部多雲、15°C、濕度 60%」*時，這項觀察會被附加到 agent 的記憶中（位於 prompt 結尾）。

接著，agent 會利用這些資訊，判斷是否需要更多資訊，或已經能提供最終答案。

這種**反覆整合回饋的過程，讓 agent 能持續朝目標前進**，根據實際結果不斷學習與調整。

觀察**可以有很多形式**，從讀取網頁文字到監測機械手臂的位置皆是如此。你可以將它視為工具的「日誌」，以文字回饋行動的執行結果。

| 觀察類型 | 範例 |
|---------------------|---------------------------------------------------------------------------|
| 系統回饋 | 錯誤訊息、成功通知、狀態碼 |
| 資料變更 | 資料庫更新、檔案系統修改、狀態變更 |
| 環境資料 | 感測器讀數、系統指標、資源使用情形 |
| 回應分析 | API 回應、查詢結果、計算輸出 |
| 時間事件 | 到達期限、排程任務完成 |

## 如何附加結果？

採取行動後，框架會依序執行以下步驟：

1. **解析行動**，找出要呼叫的函式與使用的引數。  
2. **執行行動。**  
3. **將結果附加為觀察。**
